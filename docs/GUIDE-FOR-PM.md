# 产品团队原型指引

原型是用来探索想法的，不是一次代码交付。你只说想实现什么，AI 负责把它放进独立工作区、启动和分享。`main` 的文件、分支和未提交改动都不会被触碰。

## 你只需要记住八类动作

| 你说                       | AI 会做什么                                                                                                                                       |
| :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| `基于 #123 开始原型`       | 直接复用并校验 #123，再在独立 worktree 准备并打开原型；不影响主工作区。                                                                           |
| `开始一个“Agent 记忆”原型` | 没有 Issue 时进入 local draft 草稿，不创建 Issue，也不读取或校验 Issue；Workbench 分配 `draft:<draftId>`，受管 worktree 独立准备 runtime 并启动。 |
| `分享 #123` / `分享草稿`   | 运行中或已暂停都可从当前草稿构建 ≤200 文件 ZIP，委托 WorkBuddy 内置资料库 skill 发布；不提交代码，后续覆盖同一 Page。                             |
| `暂停 #123` / `暂停草稿`   | 停止原型服务，保留同一目录和所有草稿。                                                                                                            |
| `继续 #123` / `继续草稿`   | 在原目录重新启动，草稿和分享页都还在。                                                                                                            |
| `升级草稿到 #123`          | 校验 #123 open、唯一`原型中`且含结构化 AC；保留 worktree，迁移 runtime identity，重新分享后才可冻结。                                             |
| `冻结 #123`                | 运行中或已暂停都可复验 Page/package 与 checkpoint 证据，把交接写回 Issue，转交研发并清理本地原型。                                                |
| `丢弃草稿 <draftId>`       | 不访问 Issue；确认服务已停后删除受管草稿目录，失败则保留状态供重试。                                                                              |
| `放弃 #123`                | 关闭 Issue，清理这个原型的本地目录；失败时直接提示你重试。                                                                                        |

你不需要管理分支、依赖、端口、Git 提交或部署凭据。分享不提交代码；只有说“冻结”时 AI 才固定最近分享的同一份源码并推送参考分支。它不会创建 PR 或合并到 `main`。

## 同时推进三个原型

最多同时启动 3 个原型。`draft` 草稿与 issue-bound Issue 原型共用 `ACTIVE_LIMIT=3` 三个运行槽；只有正在启动或已经启动的原型占位置。准备 worktree 不占槽，因此可以先把多个想法准备好。

启动前 AI 会重新检查运行槽。已有 3 个服务时，新原型保留为已准备状态，不启动第四个服务；暂停一个原型后即可继续。暂停会保留草稿并释放端口与位置；冻结、放弃或丢弃会按各自边界清理受管目录。

## 分享与交接

`分享`按 `share-prepare → WorkBuddy 内置资料库 skill → share-complete/share-reject` 执行，返回资料库的正式 HTTPS 链接。它按稳定 page/node 锚点反复覆盖同一 Page；外部一步导入不承诺失败后原子回退，失败会如实停止且不会伪造链接。

方向确定后，draft 先升级到真实 Issue 并重新分享，再说`冻结 #123`。研发从最新 `main` 新建自己的生产分支，以 Issue、分享页面和原型分支为参考独立实现；不会合并或整分支复用原型分支。

## 设计时只管表达效果

直接用自然语言描述界面和交互即可，例如“把首页改成任务收件箱，未读任务更醒目”。AI 仍会遵守仓库的设计系统和页面结构规范。图标暂时没有时可先占位，不要让它卡住你的探索。

## 一句话记住

> **开始、分享、暂停、继续、升级、冻结、丢弃草稿、放弃 Issue 原型；其余交给 AI，`main` 永远不受影响。**
