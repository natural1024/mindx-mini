# Quick Start — CNB 开发环境一键配置

## 背景与设计原则

- **背景**：本仓库已从「工蜂」迁移到「CNB」，后续所有开发、提交代码都在 CNB 上进行。此 skill 帮助协作者一键把本地环境配置到可开发状态。
- **面向对象**：可能完全没有编程经验的产品经理 / 设计师，以及新加入的开发者。
- **幂等原则（最重要）**：每一步都遵循「先检测，后执行」。已完成的步骤自动跳过，整套流程可以反复运行，用来查漏补缺。后续新增配置项时，同样遵循这一模式追加为新步骤。
- **零基础友好**：面向不懂技术的用户，每一步都用简明中文说明「正在做什么、结果怎样」，不要直接抛专业术语或原始报错。命令报错时，先翻译成人话再给建议。

## 执行前置检查

确认当前处于仓库根目录（存在 `package.json` 与 `pnpm-workspace.yaml`）。若不在，先 `cd` 到仓库根目录再继续。

---

## 步骤一：确保已安装 CNB CLI（幂等）

1. 运行 `which cnb` 检测是否已安装。
2. **已找到路径** → 已安装，跳过安装，告知用户「✅ CNB CLI 已安装」。
3. **未找到** → 运行 `npm install -g @cnbcool/cnb-cli` 进行安装。
4. 安装完成后再次运行 `which cnb` 复检：
   - 找到 → 安装成功。
   - 仍找不到 → 大概率是全局 bin 路径未刷新，提示用户「请关闭并重新打开终端 / IDE 后，再次运行本流程」，然后暂停后续步骤。

---

## 步骤二：确保已登录 CNB（幂等）

### 2.1 先检测登录态

运行 `cnb status`：

- **显示当前用户信息（已登录）** → 跳过登录，告知用户「✅ 已登录 CNB（用户：xxx）」。
- **未登录** → 进入 2.2 登录流程。

### 2.2 登录流程（关键：AI 如何获知用户已点击授权）

浏览器授权是发生在 AI 之外的**异步外部动作**，AI 无法监听「用户点了授权按钮」这个事件，也**不能依赖 `cnb login --woa` 命令的返回值**来判断是否登录成功（该命令可能一直阻塞等待回调，也可能提前返回，都无法可靠反映用户是否已授权）。

因此，统一采用 **「用户口头确认」+ 「`cnb status` 权威复检」** 的双保险机制来获知授权结果：

1. 运行 `cnb login --woa`。该命令会**自动打开浏览器**弹出 WOA 授权页。
   - 为避免命令阻塞卡住会话，可让其在后台运行（如在命令末尾追加 `&`）；浏览器一旦打开即可把控制权交回。
2. 明确提示用户：
   > 浏览器已自动打开授权页面，请点击页面上的「授权 / 同意」按钮完成登录。**完成后回复我一声「已授权」即可。**
3. **等待用户回复**（如「已授权」「好了」「done」）。收到回复后，再次运行 `cnb status` 作为登录状态的**唯一权威判断**：
   - `cnb status` 显示已登录 → 登录成功，告知用户「✅ 登录成功」，继续下一步。
   - `cnb status` 仍未登录 → 说明授权可能没完成（页面没点、点错、超时等）。友好告知用户，让其重新在浏览器完成授权（必要时重跑 `cnb login --woa` 重新打开授权页），再次回复确认后重新 `cnb status` 复检。如此循环，**直到 `cnb status` 通过为止**。

> 设计要点：以 `cnb status` 为登录状态的「真相源」，用用户的一句确认来触发复检。这样无论中途重试多少次都不会出错，也天然满足幂等——重复运行只会得到「已登录，跳过」。

> 补充：若 `cnb login --woa` 未在后台运行且长时间不返回（正阻塞等待授权），属于正常现象。此时先提示用户去浏览器完成授权；如需要，可中断该命令后直接进入 `cnb status` 复检，不影响最终判断。

---

## 步骤三：安装项目依赖（幂等）

运行 `pnpm install`。该命令本身幂等：依赖已齐全时会快速跳过，缺失时增量安装。

- 若提示找不到 `pnpm` → 引导用户先启用：优先 `corepack enable`（Node 自带），或 `npm install -g pnpm`，然后重跑 `pnpm install`。

---

## 完成：汇总反馈

用清单形式向用户汇总本次每一步的结果，例如：

- ✅ CNB CLI 已安装
- ✅ 已登录 CNB（用户：xxx）
- ✅ 项目依赖已安装

并提示：

> 环境已就绪。本流程可随时再次运行做环境自检 / 查漏补缺，已完成的步骤会自动跳过。

---

## 扩展指南（给后续维护者）

后续追加新的配置项时，请遵循同一套「先检测，后执行」的幂等模式：

1. 新增一个「步骤 N」，开头先做检测（命中已配置就跳过）。
2. 未配置时再执行配置动作，执行后做一次复检。
3. 把该项纳入「完成：汇总反馈」的清单。

保持每一步都能被安全地重复执行，是本 skill 的核心契约。
