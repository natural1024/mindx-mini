# Issue AC 对齐参考

旧 spec/README 需求推演已退役。需要澄清产品需求时，只为 CNB Issue 生成可验收内容，不创建第二份 PRD。

优先检查五个维度：

1. **用户与触发条件**：谁在什么前置状态下使用。
2. **可观察结果**：完成操作后界面、数据或状态发生什么变化。
3. **数据与状态**：初始、空、加载、失败、权限差异以及 mock 边界。
4. **交互边界**：取消、重复、异常、返回、刷新等行为。
5. **非目标**：本 Issue 明确不做什么。

产出写回 Issue：

```markdown
## 验收标准

- [ ] AC-1: <输入/操作/可观察结果>
- [ ] AC-2: <边界状态/可观察结果>

## 状态与数据

## 非目标
```

每条 AC 必须可独立 PASS/FAIL。更新前要求产品明确确认；prototype 代码、preview 或 README 不得覆盖 Issue。
